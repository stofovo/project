# Описание ER-диаграммы системы заказа обуви

## Состав таблиц

На диаграмме представлены семь таблиц: roles, users, products, sizes,
stock_items, orders, order_items. Для каждой таблицы указаны атрибуты,
первичные ключи (PK) и внешние ключи (FK).

## Связи между таблицами

### roles → users (1:N)

Одна роль может быть назначена многим пользователям, но каждый
пользователь имеет ровно одну роль. Связь реализована внешним ключом
users.role_id, который ссылается на roles.role_id. Ограничение
ON DELETE RESTRICT запрещает удалять роль, пока с ней связаны
пользователи.

### users → orders (1:N)

Один пользователь может оформить много заказов, но каждый заказ
принадлежит одному пользователю. Связь реализована внешним ключом
orders.user_id, который ссылается на users.user_id. Ограничение
ON DELETE RESTRICT не позволяет удалить пользователя, у которого есть
заказы.

### products → stock_items (1:N)

Одна модель обуви может иметь много товарных позиций — по одной на
каждый доступный размер. Каждая товарная позиция относится ровно к
одной модели. Связь реализована внешним ключом stock_items.product_id,
который ссылается на products.product_id, с ограничением
ON DELETE RESTRICT.

### sizes → stock_items (1:N)

Один размер встречается во многих товарных позициях, но каждая
позиция имеет ровно один размер. Связь реализована внешним ключом
stock_items.size_id, который ссылается на sizes.size_id, с ограничением
ON DELETE RESTRICT.

### orders → order_items (1:N)

Один заказ содержит много строк состава, но каждая строка принадлежит
одному заказу. Связь реализована внешним ключом order_items.order_id,
который ссылается на orders.order_id. Ограничение ON DELETE CASCADE
означает, что при удалении заказа автоматически удаляются все его
строки состава.

### stock_items → order_items (1:N)

Одна товарная позиция может встречаться в строках разных заказов, но
каждая строка состава ссылается ровно на одну товарную позицию. Связь
реализована внешним ключом order_items.stock_item_id, который ссылается
на stock_items.stock_item_id, с ограничением ON DELETE RESTRICT.

## Проверка ссылочной целостности

Для проверки работы внешних ключей была выполнена попытка вставить
пользователя с несуществующей ролью (role_id = 99). Запрос завершился
ошибкой FOREIGN KEY constraint failed. Это подтверждает, что ссылочная
целостность работает и команда PRAGMA foreign_keys = ON применяется
при подключении к базе.
